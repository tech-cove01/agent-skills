# 设计系统：画布、色、字阶、四套主题

## 1. 画布与缩放补偿

常见 GitHub 桌面主页内容列宽约 **806px**。卡片按 **962** 宽设计，在该宽度下等比缩放到 **0.84**；移动端和其他窗口宽度会不同，不能将它当成所有设备的固定尺寸。

```
实际观感 = SVG 内设计字号 × 0.84
```

**【实测校准】**（headless chrome 按 806px 宽渲染 `shi-felix` 的 hero 得到）：

| SVG 内设计值 | 实际观感 | 判断 |
|---|---|---|
| 44（大标题） | ~37 | ✅ 够大，是页面唯一焦点 |
| 15.5（副标题） | ~13 | ✅ 可读，正常正文 |
| 13（脚注） | ~11 | ⚠️ 偏小但能读，**只在页脚用** |
| ≤12 | ≤10 | ❌ 不要用 |

**推荐取值**：大标题 44-52 / 正文 15.5-18 / 脚注 13（下限）。
别再按 44→52 那样盲目放大——实测 44 在 806px 下观感已经足够。
真正需要放大的是**小字**：旧代码里写 11-12 的地方要提到 13-15.5。

## 2. Primer 色值（唯一合法取色口径）

不要自己调色。GitHub 的界面就是这套色，用别的色相一眼就能看出是外挂。
数据源：`@primer/primitives` 的 `functional/themes/{light,dark}.css`。

| 语义 | token | 亮色 | 暗色 |
|---|---|---|---|
| 主文字 | `fgColor-default` | `#1f2328` | `#f0f6fc` |
| 次文字 / 正文 | `fgColor-muted` | `#59636e` | `#9198a1` |
| 装饰文字 | `fgColor-disabled` | `#818b98` | `#656c76` |
| 边框 / 发丝线 | `borderColor-default` | `#d1d9e0` | `#3d444d` |
| 弱边框 | `borderColor-muted` | `#d1d9e0b3` | `#3d444db3` |
| 画布 | `bgColor-default` | `#ffffff` | `#0d1117` |
| 内嵌底色 | `bgColor-muted` | `#f6f8fa` | `#151b23` |
| 强调 | `fgColor-accent` | `#0969da` | `#4493f8` |
| 已合并 / 完成 | `fgColor-done` | `#8250df` | `#ab7df8` |
| 成功 / 新增行 | `fgColor-success` | `#1a7f37` | `#3fb950` |
| 注意 | `fgColor-attention` | `#9a6700` | `#d29922` |
| 危险 / 删除行 | `fgColor-danger` | `#d1242f` | `#f85149` |

⚠️ **`fgColor-subtle` 已从 Primer 移除**（2025 版起）。旧代码里常见 `#6e7681` 是废弃值，
换成 `fgColor-disabled`。`bgColor-inset` 在暗色下是 `#010409`（比画布还深），
卡片风要「凹陷」效果用它。

## 3. 对比度红线（已实测，别再凭感觉调灰）

WCAG AA 正文要求 **≥ 4.5:1**，大字号（≥18.66px bold 或 24px）要求 3:1。

| 前景 / 背景 | 实测对比度 | 结论 |
|---|---|---|
| `#1f2328` / `#ffffff` | 15.80:1 | ✅ |
| `#59636e` / `#ffffff` | 6.11:1 | ✅ 正文可用 |
| `#818b98` / `#ffffff` | **3.45:1** | ❌ 只能装饰，不能放正文 |
| `#f0f6fc` / `#0d1117` | 17.39:1 | ✅ |
| `#9198a1` / `#0d1117` | 6.50:1 | ✅ 正文可用 |
| `#656c76` / `#0d1117` | **3.57:1** | ❌ 只能装饰 |
| `#6e7681` / `#0d1117`（旧值） | 4.12:1 | ⚠️ 差一点，别用于正文 |
| `#8250df` / `#ffffff`（merged） | 5.05:1 | ✅ |
| `#ab7df8` / `#0d1117`（merged） | 6.33:1 | ✅ |

**这就是「淡灰小字显得高级」这个错觉的量化反证。** 想要层次感就用**字号 + 字重**做，
不要用更淡的灰。

## 4. 字阶系统（T1/T3 通用）

| 角色 | 字号 | 字重 | 字色 | 备注 |
|---|---|---|---|---|
| 眉行（eyebrow） | 13 mono | 600 | accent | 可截断，字距为 0 |
| 主标题 | 40-44 | 700 | default | 长名字先缩小，再截断；字距为 0 |
| 焦点数字 | 96 | 700 | default | 唯一视觉重心，字距为 0 |
| 副标题 | 18.5 | 400 | muted | |
| 列表主行（仓库名） | 21 | 700 | default | **必须压过副标题一级** |
| 列表右侧（★） | 19 | 600 | muted | 右对齐 |
| 正文 | 16 | 400 | muted | |
| 页脚 / 脚注 | 15.5 | 400 | muted | 禁用 disabled |

字体栈（含中文回退，必须写全，否则中文会掉到默认宋体）：
```
-apple-system,BlinkMacSystemFont,'Segoe UI','PingFang SC',
'Hiragino Sans GB','Microsoft YaHei',sans-serif
```
等宽：
```
ui-monospace,'SF Mono',Menlo,Consolas,monospace
```

## 5. 四套主题规格

### T1 Editorial（默认）
编辑排版 / 杂志感。**核心是「没有容器」**——靠空白、发丝线与字阶建立秩序。

- 背景：透明（两种主题下都直接融入页面）
- 无圆角、无边框、无阴影、无渐变
- 分隔：`<rect height="1" fill="borderColor-muted">` 或直接 `<line stroke-opacity=".6">`
- 主色只用一处：眉行圆点 + 关键数字/光标
- 结构：眉行 → 大标题 → 副标题 → 发丝线 → 列表 → 页脚
- 高度自适配：`H = 最后一行 y + 26 + 页脚高(44)`
- 适合：绝大多数技术岗，尤其想显「克制、有判断力」

### T2 Terminal
终端 / IDE 感。**全等宽是它的识别特征，也是它最大的坑。**

- 字体：全篇 mono
- 中文标题**不要用等宽**：中文会回退到系统字体，宽度不一致，视觉上会「跳」。
  正确做法：等宽只用于英文/数字/符号行，中文标题另起一个 `<text>` 用无衬线
- 装饰元素：提示符 `$`、静态方块光标、三圆点窗口标题栏；默认不增加动画
- 配色：画布用 `bgColor-inset`（暗 `#010409`）+ 边框，或者干脆透明只用亮色 mono 字
- 需要动画时先确认用户偏好和可访问性；默认版本保持静态，避免闪烁和持续注意力干扰
- 适合：后端 / 系统 / Agent / CLI / 基础设施方向
- 禁用：给中文段落套 mono；整屏绿字（《黑客帝国》审美 = 业余）

### T3 Card
卡片容器。**信息量大时才用，且最多 2 张卡。**

- 圆角 `rx="8"`（GitHub 自身用 6，别超过 12）
- 边框 `1px borderColor-default`
- 底色：亮 `#ffffff` / 暗 `#0d1117`（**注意：卡片风不能用透明背景**，
  否则边框会直接浮在页面底色上，失去「卡片」语义）
- 卡内边距 28，卡片间距 16
- 卡片之间**不要**再加标题，卡片内部的 eyebrow 就够
- 适合：技术栈表格化、多仓库统计、需要分区时
- 禁用：超过 2 张（第 3 张起就是仪表盘）；卡片套卡片

### T4 Minimal
零 SVG，纯 Markdown。

- 只用：`#`/`##` 标题、`---` 分割线、行内 `code`、粗体、链接
- 层次全靠「留白 + 字号递减 + 一行一个信息」
- 优势：**GitHub 搜索能索引文本**（SVG 里的字搜不到），零维护，永不坏
- 写法约束：
  - 每段 ≤ 2 行，段间空一行
  - 技术栈用 `·` 连接成一行，不用徽章
  - 项目列表用「名称 — 一句话结果」格式，结果必须在句子里
- 适合：不想维护 / 判断「装饰即噪音」/ 内容本身够硬
- 禁用：在 T4 里塞任何图片（会立刻破坏「纯文字」的一致性）

## 5.5 贡献卡（`generate_contrib.py` 产出）

主页的第二张图，承载**证据**：上面一个焦点数字，下面逐行「官方 logo + 仓库 + ★ + PR 数」。
规格固定，别每张卡重新设计。

**画布**：962 宽，高度自适应（`H = 最后一行底 + 24 + 发丝线 + 26 + 脚注 + 16`）。

| 元素 | 规格 |
|---|---|
| 页边距 | 左右 40 |
| 眉行 | `OPEN SOURCE / MERGED PULL REQUESTS`，13 mono / 600 / accent / 字距 0，前面 7×7 accent 方点 |
| 焦点数字 | 96 / 700 / 字距 0 / text 色，基线 y=152，左对齐 x=36 |
| 数字右侧标签 | `merged PRs` 18.5 muted（基线 130）+ 公开范围的仓库覆盖说明 13 muted（基线 152）；超宽截断，不声称未验证的全局排名 |
| 分隔线 | y=182，`borderColor-default`，1px |
| 列表起点 | y=206，行高 **62** |
| 仓库 logo | 30×30，`rx="7"` 圆角方形，x=40，垂直居中于两行文字。默认用 owner 官方头像（PNG 原样内嵌）；自备 SVG 若没写 `fill` 会注入主题文字色，保证亮暗都看得见 |
| 仓库名 | 19 / 700 / text，x=82，基线 row+14 |
| 仓库描述 | 13 / muted，基线 row+34，**超宽按词截断**（退到最近的空格再加 `…`） |
| star 数 | 17 / 600 / muted，右对齐 x=922，基线 row+14，前缀 `★ ` |
| PR 数 | 13 mono / 600 / accent，右对齐 x=922，基线 row+34，**1 个时写 `1 PR`** |
| 脚注 | 13 muted：`数据源 GitHub Search API（is:pr is:merged）· 每个 PR 均可在 GitHub 复核` |

**硬约束**
- 一张卡只有一个焦点数字（PR 总数）；不要把 star 总和也做成大数字，那是两套叙事
- logo 必须是 `data:` URI（外链被 CSP 拦死，见 github-rendering.md）
- 没有 logo 时退成「首字母圆角方块」，**不要让整行塌掉或留白**
- 右侧两列右对齐到同一基线，数字列宽固定 150（`reserve`），保证纵向对齐
- 卡片里不放时间点阵/热力图（信息密度低，占高不讨好）

## 6. 强调色可选集

强调色是**独立参数**，不绑主题。四选一，标准预设默认 blue：

| 名称 | 语义 | 亮色 | 暗色 | 适合 |
|---|---|---|---|---|
| purple | 已合并 / 完成 | `#8250df` | `#ab7df8` | 偏重贡献展示 |
| blue | 强调 / 链接 | `#0969da` | `#4493f8` | 默认，中性、通用 |
| green | 成功 / 增长 | `#1a7f37` | `#3fb950` | 数据增长类叙事 |
| orange | 注意 / 活跃 | `#9a6700` | `#d29922` | 不建议做主色（攻击性强） |

**只允许一个强调色 + 一个语义色**（如 purple 主 + green 表示 +lines），其余全灰阶。

## 7. 排版通用规则

- **对齐只用左对齐和右对齐**，居中会让长文本难读
- 数字用 `tabular-nums` 心智：右对齐到同一基线
- 星级缩写：`83.3k` / `1.2k` / `942`（千位以下不缩写）
- 截断按**像素**不按字符数：13.5px 比例字体实测 ≈ 6.3px/字符（0.467em），
  CJK 按 1em 计。卡片行可用宽约 740px
- 每张卡片加 `<title>`，给每个图元原生 tooltip（免费的无障碍）
- 高度一定先算再画：把每个元素的 y 列出来，检查最后一行有没有压到页脚
  （踩过：图例在 y=265，月份网格画到 y=296，直接重叠）

## 8. 新用户的风格预览

使用 `scripts/build_profile.py --gallery DIRECTORY` 生成四种风格的亮暗对比，再用自己的配置重生成。终端和卡片的贡献层也会采用对应框架；`t4` 的贡献内容始终为 Markdown，不会混入 SVG。

姓名、定位和副标题保留完整配置与图片描述，SVG 内的超长内容会缩小或截断。长行额外使用 `textLength / lengthAdjust` 约束宽度，降低系统字体差异导致的越界。仍需检查中文、英文、宽字符姓名以及窄屏，不能声称“所有字体零误差”。
