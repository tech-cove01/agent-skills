# 共享交付流程

先确定目标仓库，再读其 AGENTS 与状态入口。共同工作区存在 WORKSPACE.md 时读取对应路由；仓库专有约定和用户指令优先，不因共享目录而混合两个项目的业务状态或 Git 提交。

- CRM：docs/STATUS.md；Go 项目：docs/README.md 和其指向的实施/交接文档。不要给同一仓库另建冲突状态表。
- spec -> tickets -> implement -> code-review -> commit：定位实际调用点，明确一个可验收行为，实施后做直接相关验证及独立审查，更新证据再提交；提交失败不算完成。
- 分别在所属仓库暂存明确文件，小功能完成后提交，不批量收走另一项目或并行任务的修改。推送和外部动作按用户已有授权执行。
- 两仓的 TypeScript、SQL 与必要浏览器验证可选择对应共享 Skill。CRM 的 React 和 Agent 资料按本项目技术边界使用，不反向要求 Go/Vue 改栈。
- 根据任务选择最少必要验证，不让 Skill 的示例、固定指标或建议成为无关测试、模型排行榜、重建框架和 mock 业务交付的要求。
- 区分继承能力、历史报告、当前实测和本人新增；内部实习/求职材料不作为公开源码或自动确认的个人成果。
- 本地 .agents/skills 联接仅用于技能发现，不是应用运行依赖，也不应提交到任一 Git 仓库。不要修改用户全局技能配置。
